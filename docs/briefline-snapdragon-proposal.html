Briefline: a private, evidence-linked meeting and document copilot

Briefline turns a conversation, lecture, or working session into a trustworthy action brief without sending the user's voice, documents, or screen content to the cloud. It is designed around the AI capabilities of Snapdragon-powered HP PCs: local inference, low-latency interaction, and privacy that remains available when the user is offline.

On-device AI Snapdragon X Elite / X Plus Qualcomm AI Hub models Offline-first Accessibility

1. Executive summary

Important decisions are often lost between a live discussion and the follow-up work. Existing assistants typically require a cloud upload, produce a generic transcript, or hide the source behind an opaque summary. Briefline takes a different approach: it runs locally on an HP Snapdragon PC and creates a compact, editable brief where every proposed action is linked back to the time range or document region that supports it.

Core promise: “Your work stays on your PC, and every useful conclusion can be checked.”

The first release supports microphone capture, imported audio, pasted notes, PDFs, and images. It provides live transcription, a concise summary, decisions, action items, deadlines, open questions, and evidence links. The user can correct any result before exporting a Markdown, PDF, or shareable text brief.

2. Problem and target users

The problem

People spend the first part of a meeting listening and the second part reconstructing what happened. Cloud-only tools are not appropriate for confidential discussions, customer data, unpublished work, or unreliable connectivity.

Primary users

  • Students turning lectures into review notes and questions
  • Small teams recording decisions without a meeting secretary
  • Freelancers and consultants handling client calls privately
  • People who benefit from searchable, readable, structured notes

Briefline is deliberately narrower than a general-purpose chatbot. Its job is to preserve context, identify what changed, and make the next step explicit.

3. What is innovative

Evidence-linked output

Every decision or action has a “show evidence” control that opens the supporting transcript timestamp or source-document region. Low-confidence items are visibly marked instead of being presented as facts.

Private by architecture

Audio, transcripts, imported files, and generated briefs stay on the HP PC. Network access is not needed for the core workflow after model installation.

Conversation to work graph

Briefline groups related decisions, owners, dates, and unresolved questions into a small local graph, making follow-up more useful than a flat transcript.

Accessible interaction

The interface supports keyboard navigation, readable summaries, adjustable text size, transcript highlighting, speaker labels, and optional text-to-speech playback.

4. Technical implementation

The application is a local-first Windows desktop app with a lightweight web UI. The model choices are selected from Qualcomm AI Hub where available, then profiled on Snapdragon X hardware before packaging. The final submission will include measured results rather than unverified performance claims.

5. Data flow and privacy

Default data path

  1. Capture or import stays in the local application sandbox.
  2. Audio is chunked and passed to the local ASR model.
  3. The transcript and document text are indexed in local SQLite storage.
  4. The local generator creates structured suggestions with source offsets.
  5. The user reviews, edits, and exports the final brief.

Trust controls

  • Visible offline/local-processing status
  • Pause and delete controls for every session
  • Local-only mode enabled by default
  • Export is explicit and user initiated
  • No account required for the core workflow
  • Uncertain extractions are labeled, not silently asserted

6. Deployment and accessibility

Briefline will be distributed as a signed Windows installer for Snapdragon-powered HP PCs. The installer detects the processor and available runtime, downloads or activates the correct compiled model assets, and offers a CPU fallback where necessary. The application remains useful without an internet connection once its model assets are installed.

Hardware targets

  • Primary: HP PCs with Snapdragon X Elite
  • Compatibility target: HP PCs with Snapdragon X Plus
  • Mode selection: quality, balanced, and low-power profiles
  • Graceful fallback: CPU execution with a clear performance notice

Accessible by default

  • Full keyboard navigation and visible focus states
  • High-contrast color treatment and scalable typography
  • Transcript playback synchronized to highlighted text
  • Readable action cards instead of dense chat-only output
  • Plain-language explanations for confidence and evidence

7. Validation plan and success metrics

These are acceptance targets for the prototype, not claimed results. They will be measured on at least one Snapdragon-powered HP PC and documented in the final demo notes.

≤ 2×

Transcription real-time factor target
A 10-minute recording should process in no more than 20 minutes in the baseline profile.

≤ 5 s

Brief refresh target
A completed session should begin producing structured results within five seconds of processing completion.

100%

Evidence coverage target
Every displayed action and decision must contain a timestamp or source reference.

0

Required cloud calls
The core capture, transcription, extraction, search, and export flow must work offline.

Evaluation will include transcription quality on clean and noisy audio, extraction accuracy against a hand-labeled set of decisions and tasks, interaction latency, memory use, battery impact, installer success, and keyboard/screen-reader checks.

8. Demonstration plan

  1. Set the context: show a short client-style discussion containing a decision, an owner, a date, and an unresolved question.
  2. Show the device: briefly demonstrate that Briefline is running on the Snapdragon-powered HP PC with local mode enabled.
  3. Process live: capture a few sentences and show the transcript arriving without a network-dependent workflow.
  4. Reveal the brief: display the decisions, action cards, open questions, and evidence links.
  5. Challenge the output: open one evidence link, edit an uncertain item, and show that the correction is retained.
  6. Prove accessibility and privacy: use keyboard navigation, change text size, pause capture, and show the local data controls.
Demo line: “Briefline does not ask the user to trust a black-box summary. It shows the useful conclusion and the source that supports it, while keeping the raw work on the HP PC.”
